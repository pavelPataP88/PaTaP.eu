# AI_TASK — ROAD_REPORTS_MVP

Нужно реализовать **один** самостоятельный блок: временные дорожные отметки на карте Driver, вдохновлённые общими полезными паттернами навигационных приложений, но с оригинальной реализацией PaTaP. Не копировать код, тексты, иконки или дизайн Яндекс.Карт.

## Подтверждённые UX-паттерны

По официальной справке Яндекс.Карт полезны: короткоживущие события на карте, структурированный тип события, полоса для ДТП/работ, подтверждение «ещё есть / уже нет», срок жизни, расстояние до точки и модерация. Использовать эти принципы как общую продуктовую идею, не как материал для копирования.

## ROAD_REPORTS_MVP

Пользователь Driver с профилем должен иметь возможность поставить на карте временную отметку:
- ДТП;
- дорожные работы;
- препятствие;
- дорожный контроль;
- транспортная инспекция.

Для ДТП и работ предусмотреть структурированное уточнение полосы: все полосы / левая / средняя / правая / обочина (только если это реально понятно для текущего интерфейса).

Обязательный минимум:
1. Отчёты видны на карте как отдельный слой/маркеры, не смешиваются с GPS водителей.
2. Автору требуется аутентификация и Driver-профиль; гостевой режим может видеть только то, что безопасно показать, но ничего не создаёт.
3. У каждого типа есть разумный TTL; после истечения отметка не должна отображаться как актуальная.
4. Подтверждение «ещё актуально» / «уже нет» должно продлевать либо закрывать отметку безопасным, защищённым способом.
5. Ввод без свободного текста и без фото в первом блоке — это снижает риски модерации и публикации личных данных.
6. Автор отчёта и его GPS не должны публично раскрываться. Хранить только необходимый для защиты/лимита server-side user id.
7. Ввести проверку координат, rate limit, CSRF и ограничение расстояния до точки, если текущая модель GPS позволяет это без скрытого трекинга.
8. Не добавлять speed-trap, обход полиции, маршрутизацию в обход контроля или подсказки для нарушения закона. «Дорожный контроль» — нейтральное предупреждение о ситуации на дороге.
9. Добавить серверные и клиентские тесты: права, TTL, create/list, confirmation/closure, отсутствие утечки автора, invalid input.
10. Не трогать парковки, карту/GPS вне необходимой интеграции, чат, рацию, Caddy, минимум пароля 6, main и существующие runtime-данные.
11. В отдельной ветке от актуального `codex/local-workspace-snapshot`; обновить `AI_HANDOFF.md` с исследованием, branch, commit, файлами, реальными тестами и рисками.
12. После готового одного блока остановиться: Codex выполнит детальный review, локальные тесты и применит только при успехе.

Важно: если какой-либо пункт требует опасной переработки авторизации, GPS-приватности или непроверяемого источника данных — не реализовать его молча, а прямо отметить ограничение в AI_HANDOFF.md.
