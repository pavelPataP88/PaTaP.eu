# AI Collaboration Protocol — PaTaP.eu

Этот файл фиксирует постоянную схему работы ChatGPT и Codex над PaTaP.eu, чтобы владелец проекта не переносил сообщения вручную между системами.

## Роли

### ChatGPT / «Голова»

Главный аналитик, исследователь и разработчик.

Обязанности:
- изучает текущий код и живой продукт;
- проводит внешнее исследование рынка и лучших практик перед добавлением новых функций;
- проектирует изменения;
- пишет основной код;
- разбивает работу на маленькие независимые блоки;
- добавляет/обновляет тесты;
- документирует принятые решения;
- передаёт Codex готовый блок на проверку;
- после замечаний Codex сам исправляет код в GitHub;
- не перекладывает основную разработку на Codex без необходимости.

Причина такого распределения: Codex имеет ограниченный рабочий лимит, поэтому его ресурс надо тратить преимущественно на проверку, интеграцию с ноутбуком и production-средой, а не на повторное написание уже подготовленного кода.

### Codex / «Руки + контроль»

Проверяющий, интегратор и исполнитель на рабочем ноутбуке.

Обязанности:
- читает готовые изменения ChatGPT в GitHub;
- проверяет архитектуру, код, совместимость и риски;
- запускает локальные тесты и проверяет живую среду;
- пишет замечания ChatGPT через общий GitHub handoff;
- не переписывает большой блок заново, если достаточно указать точную проблему;
- после того как блок принят, переносит/интегрирует его в `D:\WWW.PATAP.EU`;
- собирает проект, перезапускает только необходимые процессы и проверяет живой сайт;
- создаёт новый безопасный snapshot рабочей версии после успешного применения.

Codex имеет право остановить применение блока, если находит риск потери данных, регрессию, несовместимость с локальным кодом, проблему безопасности или неуспешные тесты.

### Владелец

Владелец принимает продуктовые решения и разрешает необратимые действия. Он не должен использоваться как курьер между ChatGPT и Codex.

## Источник истины

Текущая проверенная инженерная копия production-рабочей папки:

`codex/local-workspace-snapshot`

Новые блоки должны начинаться именно от последнего подтверждённого snapshot, а не от устаревшего `main`.

После успешного внедрения блока Codex обновляет/создаёт следующий безопасный snapshot фактической рабочей версии. В snapshot не должны попадать пользователи, SQLite, сообщения, GPS, radio uploads, токены, ключи, логи, `data/`, `var/`, `node_modules/` и другие приватные/runtime-данные.

## Главное правило: только один блок за цикл

Нельзя одновременно переделывать карту, чат, рацию, интерфейс и сервер.

Примеры отдельных блоков:
- `MAP` — только карта;
- `MAP_EVENTS` — только события на карте;
- `CHAT` — только чат;
- `RADIO` — только рация;
- `CONTACTS` — только связи между водителями;
- `UI` — конкретный участок интерфейса;
- `AUTH` — авторизация;
- `PERFORMANCE` — только производительность.

Один блок должен быть достаточно маленьким, чтобы можно было понять его diff, проверить тестами и безопасно откатить.

## Цикл работы

1. **Snapshot.** ChatGPT читает последний `codex/local-workspace-snapshot`.
2. **Исследование.** Если блок продуктовый, ChatGPT изучает актуальные сильные мировые аналоги и выбирает решения, подходящие именно Driver Patap.
3. **Проектирование.** ChatGPT определяет минимальный законченный объём текущего блока и критерии готовности.
4. **Разработка.** ChatGPT пишет код и тесты в отдельной ветке, созданной от актуального snapshot.
5. **Передача.** ChatGPT записывает сообщение Codex в `AI_HANDOFF.md`: что сделано, ветка/коммиты, что проверить, что намеренно не трогалось.
6. **Проверка Codex.** Codex читает diff, запускает проверки на ноутбуке и анализирует совместимость с реальным окружением.
7. **Ответ Codex.** Codex записывает в `AI_HANDOFF.md` результат: ACCEPT / CHANGES_REQUIRED / BLOCKED, конкретные замечания и фактические результаты тестов.
8. **Исправление.** При `CHANGES_REQUIRED` ChatGPT сам исправляет код и снова передаёт его Codex. Цикл повторяется до ACCEPT.
9. **Интеграция.** После ACCEPT Codex применяет готовый блок к рабочей папке, собирает и перезапускает необходимые компоненты.
10. **Production-проверка.** Codex проверяет живые `patap.eu` и `driver.patap.eu` без необратимых действий от имени реальных пользователей.
11. **Новый snapshot.** После подтверждённого HEALTHY Codex публикует новую безопасную инженерную копию рабочей версии в GitHub.
12. Только после этого ChatGPT начинает следующий блок.

## Как ChatGPT и Codex общаются

Общий канал — файл в корне репозитория:

`AI_HANDOFF.md`

Владелец не должен копировать сообщения между системами.

Каждая запись содержит:

```text
[YYYY-MM-DD HH:MM] FROM: CHATGPT | CODEX
BLOCK: <идентификатор блока>
STATUS: READY_FOR_REVIEW | CHANGES_REQUIRED | ACCEPTED | BLOCKED | DEPLOYED
SOURCE: <ветка / commit>

Что сделано / что проверено:
...

Что требуется от второй стороны:
...

Факты тестирования:
...

Неизвестное / риски:
...
```

Новые записи добавляются сверху под заголовком `CURRENT THREAD`; старые не удаляются, пока блок полностью не завершён. После завершения блок можно свернуть в краткий итог, но историю важных решений сохранять.

## Правила для ChatGPT

- Не заявлять, что код работает, если он только написан.
- Разделять: написано / CI прошёл / локально запущено / production проверено.
- Не менять production напрямую.
- Не трогать приватные/runtime-данные.
- Не выполнять большой rewrite без необходимости.
- Не добавлять платную инфраструктуру, если есть достаточное бесплатное/локальное решение.
- Минимальная длина пароля остаётся 6 символов, пока владелец явно не изменит решение.
- Перед новым функциональным блоком проверять, не появился ли новый snapshot или сообщение Codex.

## Правила для Codex

- Не тратить лимит на повторное самостоятельное проектирование уже подготовленного блока без причины.
- Сначала ревью готового diff; затем конкретные замечания.
- Если изменение можно принять — не переписывать его ради собственного стиля.
- Если есть проблема — указать файл, место, причину, ожидаемое поведение и способ проверки.
- Не затирать более свежий локальный код.
- Не использовать `reset --hard` или другие команды с потерей данных.
- Не пушить приватные/runtime-данные.
- Применять только блок, который сейчас находится в цикле.
- После интеграции сообщать реальные команды/тесты и их результаты.

## Definition of Done блока

Блок считается завершённым только когда:
- ChatGPT закончил код и тесты;
- Codex провёл ревью;
- все обязательные замечания устранены;
- нужные автоматические тесты прошли;
- Codex применил блок на ноутбуке;
- рабочий стек снова HEALTHY;
- затронутые живые сценарии проверены;
- создан новый безопасный snapshot;
- в `AI_HANDOFF.md` стоит `DEPLOYED`.

## Общая цель

Не максимальное количество функций, а постепенно доведённый до очень высокого уровня Driver Patap: сильный, быстрый, понятный, безопасный и удобный водительский продукт. Качество каждого блока важнее скорости добавления следующего.
