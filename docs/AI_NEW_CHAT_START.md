# Новый чат: начни отсюда

Этот документ — короткая и актуальная точка входа для нового чата ChatGPT. Не восстанавливай проект по старой переписке и не считай ветку `main` актуальной.

## Где находится правда о проекте

- Рабочий сайт запущен на ноутбуке владельца. GitHub — безопасное инженерное зеркало, а не production-сервер.
- Единственная актуальная ветка исходного кода: `codex/local-workspace-snapshot`.
- Текущий snapshot — последний commit ветки `codex/local-workspace-snapshot`; не использовать старый SHA из переписки.
- Этот snapshot создан Codex из реально работающей папки сайта после установки последнего релиза.
- `main` не изменять. Новые ветки создавать только от текущего `codex/local-workspace-snapshot`.

## Что реально установлено

Последние установленные блоки: `COMMERCIAL_HARDENING_V1` и `AUD-021 AUTH_ASYNC_SCRYPT_V1`.

- PR #28 / `chatgpt/commercial-hardening-v1-work` / код `0dbfb137758a0d2c8dc62866079002740e50a4e1`.
- Добавлены безопасный экспорт данных пользователя и защищённое удаление аккаунта, обязательная проверка зависимостей, штатный Windows-автозапуск и постоянный health-watch.
- Проверка на ноутбуке прошла: Node 24, `npm ci`, `runtime:check`, `verify:release`, production preflight, шифрованная внешняя резервная копия с restore drill, build и public smoke.
- `https://patap.eu` и `https://driver.patap.eu` фактически открылись с HTTP 200 после установки.

`AUD-021` переводит обработку паролей на асинхронный scrypt в HTTP-пути входа, регистрации, сброса и удаления аккаунта. Формат прежних password hashes, параметры scrypt, auth schema 12 и минимальный пароль 6 символов сохранены. Полный Windows release suite, preflight, DR restore drill и public smoke прошли.

До этого уже были установлены и отражены в текущем snapshot: карта и Road Reports, Chat Console V2, Radio Console V2, People & Communities, Parking Network и Event Center. Их подробная история находится в `AI_HANDOFF.md` и тематических документах в `docs/`.

## Что не считать готовым

- Navigation Engine не установлен. Он заблокирован: нет проверенного реального `NAV_ROUTER_URL` с поддержкой ограничений грузовика. Нельзя подменять грузовой маршрут автомобильным.
- Не заявлять ручную проверку GPS, микрофона, динамика, чата или рации на реальных телефонах: автоматический двухпользовательский E2E прошёл, но реальную полевую проверку делает владелец/водители.
- Не утверждать, что функция работает, только потому что она есть в старой ветке или документе.

## Неприкосновенные правила

- Не публиковать и не коммитить `data/`, `var/`, SQLite, пользователей, GPS, сообщения, записи рации, медиа, токены, ключи, пароли, логи или `node_modules/`.
- Минимальный пароль регистрации — **6 символов**.
- Не менять `main`, production и локальные runtime-данные напрямую.
- Один маленький функциональный блок за раз: исследование → отдельная ветка от snapshot → код и тесты → запись в `AI_HANDOFF.md` → проверка Codex → установка только после PASS.
- Не добавлять платную инфраструктуру или выдуманные данные без отдельного решения владельца.

## Что прочитать в таком порядке

1. Этот файл.
2. `AI_TASK.md` — текущая ближайшая задача.
3. `docs/AI_COLLABORATION_PROTOCOL.md` — правила взаимодействия ChatGPT и Codex.
4. Последнюю запись `COMMERCIAL_HARDENING_V1` в `AI_HANDOFF.md` — факты последнего релиза.
5. `docs/CURRENT_ENGINEERING_STATE.md` и нужный тематический документ перед работой над конкретным блоком.

## Первое действие нового ChatGPT

Не начинать большой rewrite и не менять код вслепую. Сначала подтвердить, что основа — именно snapshot выше, кратко перечислить найденные уже работающие модули и предложить **один** следующий небольшой блок с измеримыми критериями готовности. Предложение записать в `AI_HANDOFF.md` или отдельный документ; код начинать после согласования этого блока.

## Как передавать код Codex

После выполнения блока создать отдельную ветку и записать в `AI_HANDOFF.md`:

- название блока;
- ветку и точный SHA;
- базовый SHA snapshot;
- список изменённых файлов;
- что сделано и что намеренно не делалось;
- какие тесты реально запускались и их результат;
- точные шаги проверки для Codex;
- риски и всё, что не проверялось.

Никогда не писать `DEPLOYED`, `PASS` или «работает на сайте», если это не проверил Codex на ноутбуке.
