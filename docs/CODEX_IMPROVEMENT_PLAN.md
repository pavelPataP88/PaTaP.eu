# CODEX — план улучшения PaTaP.eu

## Цель

Провести production-polish текущего PaTaP.eu / Driver Patap без переписывания продукта с нуля. Сначала сравнить локальную рабочую копию `D:\WWW.PATAP.EU` с `origin/main`: живой сайт уже показывал признаки изменений, которых могло не быть в GitHub. Не затирать более свежий локальный код.

## Жёсткие ограничения

- Минимальный пароль ОСТАВИТЬ 6 символов. Это осознанное решение владельца. Не менять backend `validatePassword`, HTML `minlength`, тексты регистрации и reset на 12 символов.
- Не публиковать и не коммитить пользователей, пароли/хеши, SQLite data, сообщения, GPS, radio uploads, токены, Cloudflare secrets, ключи, логи и runtime-данные.
- Не менять существующие аккаунты и principal Owner.
- Не удалять рабочие функции и не делать большой rewrite.
- Не менять production до локальной проверки и зелёных тестов.
- Сохранять текущую модель GPS: по умолчанию выключен; выключение прекращает публикацию координат и скрывает других водителей согласно текущей логике.

## Порядок работы

### P0 — сначала синхронизация и точные исправления

1. Сравнить локальный HEAD/working tree с `origin/main`. Если локальная версия новее, сначала сохранить её в GitHub отдельным понятным коммитом/веткой. Не делать `reset --hard` и не перезаписывать локальные изменения.
2. Зафиксировать поддерживаемую версию Node, потому что backend использует `node:sqlite`. Предпочтительно Node 22 LTS: добавить `engines` в `package.json`, `.nvmrc` (или эквивалент для Windows) и явное требование версии в DEV/RUNBOOK. Проверить фактическую минимальную версию перед выбором точного `>=`.
3. Исправить malformed JSON: некорректное JSON-тело API должно возвращать HTTP 400 с стабильной безопасной ошибкой, а не 500 `server_error`. Добавить тест минимум для `/api/login` и желательно общего body parser.
4. Исправить Caddy edge-case `X-Forwarded-Proto: http`: запрос к `driver.patap.eu` должен редиректить на `https://driver.patap.eu{uri}`, а основной хост — на `https://patap.eu{uri}`. Добавить автоматическую проверку обоих сценариев.
5. Добавить favicon/manifest icon или корректно убрать запрос, чтобы `/favicon.ico` не давал бессмысленный 404.

### P0 — производительность статики

6. Не ставить один `no-store` на всё подряд. HTML и чувствительные/API ответы могут оставаться `no-store`; статические версированные assets/vendor должны получать безопасный долгий cache (`public, max-age=31536000, immutable`) только если URL действительно versioned/content-stable. Не кэшировать приватные API и персональные ответы.
7. Проверить размеры фоновых изображений. Большие PNG конвертировать в WebP/AVIF с fallback, сохранив визуальное качество. Оригинал не публиковать, если он намеренно исключён.
8. MapLibre: проверить, загружается ли ~тяжёлый JS/CSS гостю до необходимости. В гостевом режиме используется демонстрационная карта — реальный MapLibre желательно лениво загружать только для авторизованной интерактивной карты. Не ломать карту и CSP.
9. Добавить performance budget/проверку хотя бы для основных initial assets, чтобы тяжёлые файлы случайно не вернулись.

### P1 — надёжность и архитектура

10. Разгрузить `server/auth/server.js` без большого rewrite: вынести логически самостоятельные route handlers/middleware (body parsing/errors, session/auth helpers, admin routes) только если это уменьшает связанность и тесты остаются зелёными. Делать маленькими шагами.
11. `/api/health`: наружу отдавать минимум информации (`ok`), подробную диагностику БД не раскрывать публично без необходимости. Убедиться, что внутренние healthchecks продолжают работать.
12. Проверить частоту записи `last_seen_at` в SQLite. Если она происходит на каждом авторизованном запросе, добавить разумный throttle/debounce (например, обновлять не чаще заданного интервала), не ломая истечение/ревокацию сессий.
13. Чётко документировать границу legacy root UI и PlatformOS. Не создавать две параллельные истины. Либо текущий production shell явно обозначить как shell, либо постепенно переводить runtime на registry-driven модель отдельными проверяемыми PR/коммитами.
14. Добавить нормальный `docs/DEV.md`: чистый clone -> правильная Node -> `npm ci` -> build -> verify -> локальный запуск без зависимости от личного `D:\WWW.PATAP.EU` и production-домена. Windows-инструкции можно оставить отдельно.
15. Добавить `SECURITY.md` с безопасным способом сообщать об уязвимостях. `LICENSE` НЕ добавлять автоматически: публичный репозиторий не означает разрешение на использование. Сначала владелец должен выбрать лицензионную политику.

### P1 — полный E2E Driver

16. Создать E2E, покрывающий основную ценностную цепочку, с тестовыми изолированными данными:
   - регистрация водителя;
   - вход;
   - создание/редактирование профиля;
   - GPS off по умолчанию;
   - GPS on и публикация тестовой позиции;
   - nearby второго тестового водителя;
   - поиск по нику;
   - запрос/подтверждение контакта;
   - direct chat;
   - direct radio (где возможно в автоматизированной среде — API/моки MediaRecorder, без реального микрофона);
   - block и проверка ограничения взаимодействия;
   - GPS off и подтверждение удаления/скрытия location.
17. E2E не должен использовать production users/GPS/messages. Временная БД и временное storage должны удаляться после теста.
18. Проверить mobile viewport Driver, отсутствие критического вертикального overflow в основных экранах и работоспособность навигации touch.

### P1/P2 — UX Driver

19. Карта: визуально различать хотя бы тип водителя (`TIR`, `TAXI`, `DELIVERY`, `GENERAL`) и состояние отношений (контакт/не контакт), не превращая карту в шум. Сначала предложить простой вариант и проверить на мобильном.
20. Карточка водителя должна ясно показывать доступные действия и почему действие недоступно (например, рация только подтверждённому контакту).
21. Добавить понятные состояния загрузки/skeleton/fallback вместо долгого зависания `Проверяем аккаунт Patap…`. При ошибке auth/API пользователь должен быстро попасть в корректный guest/login/error state.
22. Технические ошибки преобразовывать в человеческие сообщения; подробности оставлять в безопасном серверном журнале, не в UI.
23. Добавить `prefers-reduced-motion`, проверить focus states/keyboard navigation и базовую доступность форм/кнопок.
24. Админка: заменить `window.prompt` для reset token на нормальный modal с Copy и явным предупреждением, что токен показывается ограниченно. Поиск/фильтр/пагинацию добавлять только когда объём пользователей это оправдывает.

### P2 — приватность и рост, не блокирует ближайший релиз

25. Подготовить дизайн (не обязательно сразу реализовывать) для: точности GPS/`что видят другие`, fuzzy location для неконтактов, quiet/home zones, статусов водителя (`свободен`, `занят`, `отдых`, `погрузка`), low-data/PWA режима.
26. Не внедрять fuzzy/quiet zones без ясной модели поведения: безопасность и предсказуемость важнее количества функций.
27. OpenStreetMap tiles: текущий вариант допустим для малого использования, но перед ростом нагрузки проверить tile usage policy и выбрать устойчивую схему (provider/cache/self-host) без преждевременной инфраструктуры.
28. Операционка ноутбука: проверить автозапуск/перезапуск Node, Caddy и cloudflared, health monitoring, log rotation, backup SQLite и реальный restore drill. Ничего необратимого не делать без владельца.
29. Физически очищать просроченные radio-файлы согласно retention-модели и тестировать очистку.
30. Добавить минимальный accessibility smoke и разумный performance check в CI. Visual regression вводить только если он реально стабилен и не создаёт постоянный шум.

## Что НЕ делать сейчас

- Не менять минимум пароля с 6 символов.
- Не внедрять обязательный 2FA/WebAuthn сейчас; можно оставить roadmap для Owner/Admin.
- Не строить собственный tile server только ради архитектурной красоты.
- Не добавлять email verification/reset, пока не выбран способ доставки без лишней платной инфраструктуры. Текущий admin reset оставить рабочим.
- Не переписывать приложение на framework и не менять стек без доказанной необходимости.
- Не добавлять `LICENSE` без решения владельца.
- Не менять публичный production напрямую до проверки локальной версии.

## Критерии готовности

Перед применением на рабочем ноутбуке:

1. `npm ci` проходит на заявленной версии Node.
2. `npm run build` проходит.
3. `npm run verify` проходит.
4. `npm run test:browser` проходит.
5. Новый malformed-JSON test проходит и подтверждает HTTP 400.
6. Проверка Caddy подтверждает сохранение `driver.patap.eu` при HTTP->HTTPS redirect.
7. Guest Patap и Guest Driver открываются без реальных данных.
8. Авторизованный Driver: профиль, GPS, nearby, contacts, chat и radio не регрессировали.
9. GPS по умолчанию выключен; после выключения координаты не остаются публично видимыми.
10. В git diff нет `data/`, `var/`, secrets, tokens, logs, SQLite, пользовательских сообщений/GPS/radio uploads.
11. Перед production deployment показать владельцу краткий diff: что изменено, какие тесты реально запускались и что осталось непроверенным.

## Правило исполнения для Codex

Не выполнять этот документ механически одним огромным коммитом. Сначала аудит фактического локального состояния, затем маленькие логические изменения. После каждого рискованного блока запускать релевантные тесты. Если локальный код расходится с GitHub, локальные рабочие изменения считать потенциально более свежими и не затирать. Все предположения сначала проверять по коду/живому окружению.
